# Задание для наполнения карточек компонентов

Ты — технолог-косметолог и специалист по сырью. Твоя задача: для **одного**
компонента из плана подготовить полную карточку в формате каталога
«Косметическая база» и записать её в файл.

## Что нужно сделать

1. Прочитай план: `F:\cosmetic-compound-base\data\new-30-plan.json`.
   Найди в нём **свой** компонент по полю `key` (он указан в задании).
2. Прочитай образец готовой карточки: `F:\cosmetic-compound-base\data\example-item.json`.
   Это реальная запись из каталога — по ней видно требуемый стиль, глубину и структуру.
3. Собери по компоненту достоверную информацию (черпай из проверяемых источников:
   CosIng, PubChem, ECHA, документация производителей, учебники по косметической
   химии, обзоры в рецензируемых журналах).
4. Сформируй JSON-объект записи (поля — как в образце, без ключа `example_source`).
5. **Запиши его в файл**, путь указан в плане в поле `out`
   (например `F:\cosmetic-compound-base\data\enriched-new\ectoin.json`).
   Запись файла обязательна — именно файл является результатом работы.

## Обязательные требования к качеству

| Поле | Требование |
|---|---|
| `description` | **не короче 900 знаков** (у образца — около 2000). Химия, идентификация, товарная форма, где и зачем применяется, преимущества и ограничения |
| `tech_protocol` | **не короче 700 знаков**. Как именно вводить: в какую фазу, при какой температуре, какой pH, скорость и время перемешивания, порядок добавления, типичные ошибки |
| `typical_usage` | конкретные проценты ввода по типам продуктов |
| `references` | **минимум 3 ссылки**, только реально существующие URL (CosIng, PubChem, ECHA, производитель, научная статья) |
| `cas` | действительный номер CAS. Если вещество — смесь или полимер с переменным составом, укажи это словами и приведи номера |
| `inci` | строго по номенклатуре INCI (как в CosIng) |
| `synonyms` | массив: торговые названия и распространённые синонимы |
| `components` | массив: для смесевых продуктов — состав по INCI; для индивидуальных веществ — пустой массив |
| `extra` | словарь: `EINECS`/`CAS`-уточнения, `trade_names`, `HLB`, иные полезные пометки |

Никаких выдуманных данных. Если точное значение неизвестно — напиши это прямо
в тексте (например «точное значение производитель не раскрывает») и поставь
`data_confidence` в `medium`.

## Схема записи (все поля обязательны)

```json
{
  "id": "латиница-через-дефис",         // из плана, поле key
  "provenance": "ai",
  "name_ru": "...",                     // из плана
  "name_lat": "...",                    // международное название
  "inci": "...",                        // из плана
  "cas": "...",
  "category": "...",                    // из плана
  "category_note": "",
  "aggregate_state": "твёрдое вещество (порошок) | жидкость | паста | ...",
  "origin": "натуральное | синтетическое | полусинтетическое | минеральное",
  "origin_details": "из чего и как получают, 200+ знаков",
  "description": "подробное описание, 900+ знаков",
  "function_in_formula": "роли через точку с запятой",
  "tech_protocol": "технология ввода, 700+ знаков",
  "typical_usage": "проценты ввода по продуктам",
  "ph_range": "рабочий диапазон pH",
  "solubility": "растворимость",
  "compatibility_notes": "с чем совместим, с чем нельзя",
  "regulatory": "ограничения ЕС/РФ, приложения Регламента 1223/2009, ТР ТС 009/2011",
  "synonyms": ["..."],
  "components": [],
  "references": [{"title": "...", "url": "https://..."}],
  "data_confidence": "high | medium | low",
  "confidence_notes": "что подтверждено, что вызывает сомнения",
  "extra": {"trade_names": "..."},
  "source_name": "ИИ: подбор по рынку (30 новых компонентов)",
  "source_inci": ""
}
```

## Стиль текста

* Пиши по-русски, технически точно, без маркетинговых преувеличений.
* В `description` указывай INCI, русское название, CAS и синонимы в первых
  предложениях — как в образце.
* Объясняй **почему** компонент работает так, а не только что он делает.
* Указывай ограничения и типичные ошибки применения.
* Не используй фразы «лучший», «уникальный», «революционный».

## Проверка перед записью

* длина `description` ≥ 900 знаков;
* длина `tech_protocol` ≥ 700 знаков;
* `references` — не меньше 3, все URL начинаются с `https://`;
* JSON разбирается без ошибок (проверь перед записью);
* файл записан в путь из поля `out`.

## Что вернуть в ответе

Короткий отчёт: ключ компонента, название, путь к записанному файлу, длины
`description` и `tech_protocol`, число ссылок, уровень достоверности и одна
строка о том, что вызвало сложности. Ответ должен быть коротким — сама карточка
идёт в файл, а не в ответ.
