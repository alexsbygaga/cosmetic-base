# Публикация каталога на GitHub: пошагово

Инструкция рассчитана на то, что вы делаете это впервые. Проходите шаги по
порядку, после каждого есть проверка — так видно, что всё идёт правильно.

**Что получится:** сайт с каталогом на бесплатном адресе GitHub Pages.
Отдушки в эту версию **не попадут**: в статической публикации входа нет, поэтому
скрытые категории из неё исключаются автоматически (и это проверяется при сборке).

**Чего не будет:** редактирования прямо на сайте. Для правок используется ваш
компьютер (вариант A из [publish-without-cloud.md](publish-without-cloud.md)),
а на GitHub переносится готовый файл каталога.

Общее время: 20–30 минут.

---

## Шаг 0. Откройте папку проекта в PowerShell

Это важно: команды запускаются **из папки проекта**, иначе Node не найдёт скрипты
и вы увидите ошибку вида `Cannot find module ...\tools\github-setup.mjs`.

```powershell
cd /d F:\cosmetic-compound-base
```

Ключ `/d` нужен, если PowerShell сейчас на другом диске (например, на `C:`).
Проверить, что вы в нужной папке:

```powershell
Get-Location
```

Должно вывести `F:\cosmetic-compound-base`. Если да — все команды ниже можно
копировать и вставлять как есть.

> В новых окнах PowerShell папка сбрасывается на домашнюю (`C:\Users\...`),
> поэтому эту команду нужно выполнять при каждом новом окне.

---

## Шаг 1. Что должно быть установлено

Откройте PowerShell в папке проекта и выполните:

```powershell
node tools/github-setup.mjs check
```

Скрипт проверит всё и покажет, чего не хватает. Он ничего не меняет — только
смотрит. Каждый пункт помечается:

* `[ок]` — всё в порядке, ничего делать не нужно;
* `[!]` — предупреждение, посмотрите пояснение ниже;
* `[нет]` — это нужно исправить, инструкция появится тут же.

**Git** — программа, которая отправляет файлы на GitHub. Если её нет:

```powershell
winget install --id Git.Git -e
```

После установки **закройте и откройте PowerShell заново** (иначе команда `git`
не найдётся), затем снова перейдите в папку проекта (`cd /d F:\cosmetic-compound-base`).
Проверьте: `git --version`.

**Имя и почта для коммитов.** Это подпись, которой помечаются ваши изменения.
Почта должна совпадать с той, на которую зарегистрирован GitHub:

```powershell
git config --global user.name "Ваше Имя"
git config --global user.email "ваша@почта"
```

Повторите `node tools/github-setup.mjs check` — все пункты должны быть `[ок]`.

> Если вы видите предупреждение «в этом окружении нельзя запускать git напрямую» —
> это нормально в ограниченных средах, скрипт просто проверил git по файлам.
> На обычном компьютере такого сообщения не будет.

---

## Шаг 2. Аккаунт и пустой репозиторий на GitHub

1. Зарегистрируйтесь на <https://github.com>, если аккаунта ещё нет.
   **Важно:** сразу настройте двухфакторную защиту через **приложение**
   (Google Authenticator, Authy и подобные), а не через SMS: доставка SMS
   в код +375 работает ненадёжно, и так можно потерять доступ к аккаунту.
   Сохраните резервные коды в надёжном месте.

2. Создайте репозиторий: нажмите **+** в правом верхнем углу → **New repository**.

   | Поле | Что указать |
   |---|---|
   | Repository name | например `cosmetic-base` |
   | Description | необязательно |
   | Public / Private | **Private** — рекомендую: каталог и история правок останутся закрытыми, а сайт всё равно будет доступен |
   | Add a README file | **не ставить галочку** |
   | Add .gitignore | **None** |
   | Choose a license | **None** |

   > Про доступность сайта из Private-репозитория: GitHub Pages работает и с
   > приватными репозиториями на бесплатном тарифе, но **сам сайт публичный** —
   > его увидят все, у кого есть ссылка. Приватность репозитория означает лишь,
   > что исходники и история изменений закрыты.

3. Нажмите **Create repository**. Откроется страница с адресом вида
   `https://github.com/ваш-логин/cosmetic-base.git` — он понадобится на шаге 4.

## Шаг 3. Первый коммит

В PowerShell в папке проекта:

```powershell
node tools/github-setup.mjs init
```

Скрипт:
* создаст репозиторий и ветку `main`;
* дополнит `.gitignore`, чтобы **пароли, сессии и служебные папки не ушли на GitHub**;
* соберёт статическую версию каталога без отдушек;
* проверит, что среди файлов к отправке нет `data/auth/`, `.tunnel/` и `node_modules/`;
* сделает первый коммит.

Если скрипт напишет, что в коммит попали служебные файлы — **остановитесь** и
напишите мне: это значит, что `.gitignore` не сработал.

---

## Шаг 4. Отправка на GitHub

Подставьте адрес своего репозитория из шага 2:

```powershell
node tools/github-setup.mjs publish https://github.com/ваш-логин/cosmetic-base.git
```

При первом обращении GitHub попросит войти — откроется окно браузера,
разрешите доступ («Sign in with your browser»). Это стандартный вход, пароль
в консоли вводить не нужно.

Если всё прошло, скрипт напишет, что код отправлен.

---

## Шаг 5. Включение сайта

Это единственный шаг, который делается только на сайте GitHub — из консоли
его выполнить нельзя.

1. Откройте свой репозиторий на GitHub.
2. **Settings** (вверху справа) → в левом меню **Pages**.
3. В блоке **Build and deployment** → **Source** выберите **GitHub Actions**.
4. Перейдите на вкладку **Actions**. Там появится запуск с названием
   «Публикация каталога на GitHub Pages». Дождитесь **зелёной галочки**
   (обычно 1–2 минуты).
5. Вернитесь в **Settings → Pages**: вверху будет адрес сайта вида
   `https://ваш-логин.github.io/cosmetic-base/`.

Откройте этот адрес — каталог должен открыться. Отдушек в нём не будет,
и это правильно.

> Если вкладка Actions показывает красный крестик — откройте упавший запуск и
> пришлите мне текст ошибки, разберусь.

## Как обновлять каталог

Правки вносятся на вашем компьютере, затем переносятся на сайт.

1. Откройте локальный сайт (<http://127.0.0.1:8787>), войдите под своим
   администратором и правьте каталог как обычно — изменения сохраняются
   в `data/materials.json`.
2. Соберите статическую версию:

   ```powershell
   python tools/sync-web-data.py
   ```

3. Отправьте изменения на GitHub:

   ```powershell
   node tools/github-setup.mjs status     # посмотреть, что изменилось
   git add -A
   git commit -m "Обновление каталога"
   git push
   ```

4. GitHub Actions сам пересоберёт и обновит сайт за 1–2 минуты.

Проверить состояние в любой момент:

```powershell
node tools/github-setup.mjs status
```

## Что важно помнить

* **Отдушки не попадают в публикацию.** Их исключает
  [tools/sync-web-data.py](../tools/sync-web-data.py), а workflow дополнительно
  проверяет это и останавливает сборку, если скрытые позиции просочились.
* **Секреты не уходят на GitHub.** `data/auth/` (хеши паролей и сессии) и
  `.tunnel/` перечислены в `.gitignore`. Скрипт `init` проверяет это перед коммитом.
* **Правки на опубликованном сайте не сохраняются** — в статической версии нет
  сервера. Меню «Данные каталога» там работает только на скачивание.
* **Адрес GitHub Pages может быть недоступен из Беларуси** — перебои случаются.
  Если это критично, основной ссылкой лучше сделать вариант с Cloudflare Tunnel,
  а GitHub держать как зеркало.

## Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| `Cannot find module ...\tools\github-setup.mjs` | Команда запущена не из папки проекта. Выполните `cd /d F:\cosmetic-compound-base` и повторите |
| `git: команда не найдена` | Git не установлен или PowerShell не перезапущен после установки |
| `git не знает автора коммита` | Задайте `git config --global user.name` и `user.email` (шаг 1) |
| Предупреждение «нельзя запускать git напрямую» | Ничего делать не нужно: скрипт проверил git по файлам |
| `отправка не удалась` | Проверьте адрес репозитория (шаг 2) и что репозиторий создан пустым |
| В коммит попали `data/auth/...` | Не отправляйте! Напишите мне — поправлю `.gitignore` |
| Сайт открывается, но пустой | Посмотрите Actions: возможно, сборка упала; пришлите ошибку |
| 404 на адресе сайта | Pages ещё не включён (шаг 5) или сборка не завершилась |
| Каталог устарел | Забыли `git push` или не дождались окончания сборки |
| Не могу войти в GitHub | Используйте резервные коды; SMS в +375 ненадёжен |
