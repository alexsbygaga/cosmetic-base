# Публикация каталога, если Oracle недоступен

Oracle Cloud не регистрирует пользователей из Беларуси, и обойти это нельзя.
Ниже — рабочие варианты, которые не требуют зарубежной карты и зарубежной
регистрации. Первый из них позволяет опубликовать сайт **уже сегодня, бесплатно
и с полным функционалом**, включая редактирование.

| Вариант | Стоимость | Правки сохраняются | Что нужно |
|---|---|---|---|
| **A. Свой компьютер + Cloudflare Tunnel** | 0 | да, на вашем диске | включённый компьютер |
| **B. VPS в Беларуси или СНГ** | ~10–30 BYN/мес | да, на диске VPS | оплата картой РБ или ЕРИП |
| **C. Статика на GitHub Pages** | 0 | нет, через коммит файла | аккаунт GitHub |
| **D. Статика на любом другом хостинге** | 0–5 BYN/мес | нет, через файл | загрузка файла на хостинг |

Важно: инструкция [deploy-oracle.md](deploy-oracle.md) остаётся полезной для
варианта B — набор `deploy/` рассчитан на обычный Linux-сервер и подходит
любому провайдеру, а не только Oracle.

**Почему на GitHub нельзя повторить сервер как в Oracle.** GitHub предоставляет
только статический хостинг и сборку. Серверный процесс с постоянным диском там
запустить нельзя: раннеры GitHub Actions выдаются на время задачи и стираются
после неё. Нашему приложению нужен именно постоянный диск — в него пишутся
правки каталога и файлы пользователей. Поэтому на GitHub получается **каталог
для просмотра**, а не редактируемая база. Для редактирования — варианты A или B.

---

## Вариант C. GitHub Pages (бесплатно, только просмотр)

Подходит, если нужно показать каталог по постоянной ссылке. Всё уже
подготовлено: workflow [.github/workflows/pages.yml](../.github/workflows/pages.yml)
публикует папку `web/` при каждом коммите.

### Как включить

1. Создайте репозиторий на GitHub и загрузите проект (папку целиком).
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Сделайте коммит в ветку `main` — workflow соберёт и опубликует сайт.
4. Через минуту сайт откроется по адресу вида
   `https://имя-пользователя.github.io/имя-репозитория/`.

Локально статику можно собрать и проверить так:

```powershell
python tools/sync-web-data.py      # копирует каталог в web/data/materials.json
# папка web/ готова к публикации
```

### Как обновлять каталог

Правки в этой версии не сохраняются на сервере — их нужно переносить файлом:

1. Откройте сайт, внесите правки в браузере (они сохранятся у вас локально).
2. Меню «Данные каталога» → **«Скачать каталог (JSON)»**.
3. Замените этим файлом `data/materials.json` в проекте и закоммитьте.
   Workflow обновит `web/data/materials.json` и переопубликует сайт.

### Что важно знать про GitHub из Беларуси

* Беларусь входит в [список стран, поддерживаемых для SMS-подтверждения](https://docs.github.com/ru/authentication/securing-your-account-with-two-factor-authentication-2fa/countries-where-sms-authentication-is-supported),
  однако на доставку SMS в код +375 есть [жалобы пользователей](https://github.com/orgs/community/discussions/197642).
  Поэтому сразу настройте приложение-аутентификатор (TOTP) вместо SMS
  и сохраните резервные коды — иначе можно потерять доступ к аккаунту.
* Доступ к **GitHub Pages** из Беларуси периодически ограничивается; о перебоях
  сообщали [местные СМИ](https://devby.io/news/problemy-s-dostupom-k-github-pages).
  Поэтому постоянную рабочую ссылку лучше делать через вариант A или B, а GitHub
  использовать как дополнительную площадку. Если сайт нужен только для
  показа и вы зарегистрированы в другом сервисе — подойдёт и вариант D.

## Вариант D. Статика на любом другом хостинге

Папка `web/` — обычные статические файлы, её можно выложить куда угодно:
на бесплатный или дешёвый хостинг, в том числе белорусский, с оплатой через
ЕРИП, либо на GitLab Pages и подобные сервисы.

1. `python tools/sync-web-data.py`
2. Выложите содержимое папки `web/` на хостинг: по FTP, через панель
   управления или загрузкой архива.
3. Правки переносите так же, как в варианте C, шаг «Как обновлять каталог».

## Вариант A. Свой компьютер + Cloudflare Tunnel (бесплатно, с редактированием)

Ваш компьютер остаётся сервером, а Cloudflare даёт публичный адрес и HTTPS.
Никаких входящих портов, белого IP и регистрации в зарубежных облаках.
Нужен только бесплатный аккаунт Cloudflare и домен.

### Шаг 1. Установите cloudflared

```powershell
winget install --id Cloudflare.cloudflared
```

Если winget не работает — скачайте `cloudflared-windows-amd64.exe` со
[страницы релизов](https://github.com/cloudflare/cloudflared/releases/latest),
переименуйте в `cloudflared.exe` и положите в папку проекта.

### Шаг 2. Запустите приложение

```powershell
npm start
```

Проверьте: <http://127.0.0.1:8787> открывается, каталог на месте.

### Шаг 3. Домен

Здесь два варианта.

**Если домена нет.** Запустите временный адрес — он выдаётся сразу, без
регистрации и без аккаунта Cloudflare:

```powershell
node tools/tunnel.mjs free
```

В консоли появится адрес вида `https://что-то-случайное.trycloudflare.com`.
Он работает, пока запущена команда, и **меняется при каждом перезапуске** —
годится для демонстрации, но не для постоянной ссылки.

**Если есть домен.** Добавьте его в Cloudflare (бесплатный тариф, NS-серверы
регистратора нужно переключить на Cloudflare) либо купите домен у регистратора,
который принимает местную оплату. Затем:

```powershell
$env:CB_TUNNEL_DOMAIN = "base.ваш-домен.by"
node tools/tunnel.mjs setup
```

Скрипт откроет браузер для входа в Cloudflare, создаст туннель, пропишет
DNS-запись и сохранит конфигурацию в `.tunnel/config.yml`.

### Шаг 4. Запустите туннель

```powershell
node tools/tunnel.mjs run
```

Адрес `https://base.ваш-домен.by` начнёт открываться. Проверить состояние в
любой момент:

```powershell
node tools/tunnel.mjs status
```

### Шаг 5. Автозапуск после перезагрузки

Нужно, чтобы поднимались **две вещи**: приложение и туннель.

**Windows.** Проще всего через «Планировщик заданий»:

1. Откройте «Планировщик заданий» → «Создать задачу».
2. Имя: `Косметическая база`.
3. Вкладка «Триггеры» → «Создать» → «При входе в систему».
4. Вкладка «Действия» → «Создать» → «Запуск программы»:
   * программа: `node`
   * аргументы: `server\serve.mjs`
   * рабочая папка: путь к проекту
5. Повторите то же самое для туннеля:
   * программа: `node`
   * аргументы: `tools\tunnel.mjs run`
   * рабочая папка: путь к проекту
6. В свойствах задачи включите «Выполнять вне зависимости от регистрации
   пользователя», если компьютер используется как сервер.

**Linux или Raspberry Pi.** Скопируйте `deploy/cosmetic-base.service` (это
готовый unit) и создайте второй unit для туннеля:

```ini
# /etc/systemd/system/cosmetic-base-tunnel.service
[Unit]
Description=Cloudflare Tunnel для каталога «Косметическая база»
After=network-online.target cosmetic-base.service
Wants=network-online.target

[Service]
Type=simple
User=cosmetic
WorkingDirectory=/opt/cosmetic-base/app
Environment=CB_TUNNEL_DOMAIN=base.ваш-домен.by
ExecStart=/usr/bin/node /opt/cosmetic-base/app/tools/tunnel.mjs run
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now cosmetic-base cosmetic-base-tunnel
```

### Что важно знать

* Пока компьютер выключен или в спящем режиме — сайт недоступен. Настройте
  отключение сна: «Параметры → Система → Питание → Переход в спящий режим: Никогда».
* Данные лежат в `data/` на вашем диске. Делайте резервные копии:
  скрипт `deploy/backup.sh` рассчитан на Linux, для Windows просто копируйте
  папку `data` в надёжное место (в том числе `data/auth` — там пароли и сессии).
* Локальный доступ (`http://127.0.0.1:8787`) продолжает работать, правки на
  сервере видны сразу.

## Вариант B. VPS в Беларуси или СНГ (недорого, надёжно)

Если нужен сайт, работающий круглосуточно без вашего компьютера, подойдёт
недорогой VPS с местной оплатой. Порядок цен: общий хостинг от ~10 BYN/мес,
VPS от ~55 BYN/мес (например, [тарифы mhost.by](https://www.whtop.com/ru/plans/mhost.by/133479)).
Оплата — карта белорусского банка или ЕРИП, зарубежный сервис не нужен.

Плюс: **весь набор `deploy/` уже готов** — он писался для обычного Linux-сервера
и не привязан к Oracle.

1. Возьмите VPS с Ubuntu 22.04 или 24.04 (1 ядро, 1–2 ГБ памяти достаточно).
2. Загрузите проект и запустите установку:

```bash
mkdir -p ~/cosmetic-base && tar -xzf ~/cosmetic-base-*.tar.gz -C ~/cosmetic-base
cd ~/cosmetic-base
sudo ./deploy/setup-oracle.sh --domain ваш-домен.by
```

Скрипт поставит Node.js и Caddy, настроит HTTPS, автозапуск, бэкапы и firewall.
3. Создайте администратора:

```bash
sudo -u cosmetic CB_DATA_DIR=/var/lib/cosmetic-base \
  node /opt/cosmetic-base/app/server/create-admin.mjs admin 'ВашПароль123'
```

Если домена нет — направьте на адрес VPS любой A-поддомен, Caddy выпустит
сертификат автоматически. Для VPS без домена можно использовать тот же
Cloudflare Tunnel (вариант A, шаг 3–4), только уже на сервере: тогда домен не
нужен вовсе, а HTTPS обеспечит Cloudflare.

## Вариант C. Только статика (просмотр без правок)

Подходит, если нужно просто показать каталог, а правки вносить редко.
Работает на любом бесплатном или дешёвом хостинге, включая белорусский.

Ограничение: правки, сделанные в браузере, видны только вам (они хранятся в
браузере). Чтобы обновить каталог для всех, нужно заменить файл данных.

Порядок работы:

1. Откройте сайт и внесите правки.
2. Меню «Данные каталога» → **«Скачать каталог (JSON)»**.
3. Положите скачанный файл как `data/materials.json` в папке `web/`
   (или пришлите его мне — я обновлю репозиторий).
4. Выложите содержимое папки `web/` на хостинг: по FTP, через панель
   управления или загрузкой архива.

Хостинг подойдёт любой, поддерживающий статические файлы, в том числе
белорусские провайдеры с оплатой через ЕРИП. Бесплатные зарубежные варианты
(GitHub Pages и подобные) для Беларуси ненадёжны: доступ к GitHub Pages
периодически ограничивается, о чём сообщали [местные СМИ](https://devby.io/news/problemy-s-dostupom-k-github-pages).

## Сравнение: что выбрать

* **Хочу бесплатно и с редактированием сегодня** → вариант A. Компьютер должен
  быть включён; для постоянной работы лучше подойдёт Raspberry Pi или старый
  ноутбук.
* **Хочу сайт, работающий всегда, без своего компьютера** → вариант B:
  VPS за 10–30 BYN/мес с оплатой через ЕРИП.
* **Хочу бесплатную постоянную ссылку и правки вносить редко** → вариант C
  (GitHub Pages) или D.
* **Хочу и то, и другое** → сайт на варианте A или B (там работает вход и
  редактирование), а GitHub Pages держать как зеркало для просмотра: правки
  переносятся одним файлом `materials.json`.

В любом случае ядро проекта менять не нужно: сервер работает и на вашем
компьютере, и на VPS, и в связке с туннелем. Отличается только способ доставки
трафика до приложения.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `cloudflared не найден` | установите через `winget` или положите `cloudflared.exe` в папку проекта |
| Адрес не открывается | запущены ли **оба** процесса: `npm start` и `node tools/tunnel.mjs run`; проверьте `node tools/tunnel.mjs status` |
| Домен не открывается | DNS-запись создана? В Cloudflare должен быть CNAME на адрес туннеля; подождите 5–10 минут |
| Сайт пропал после перезагрузки | не настроен автозапуск (шаг 5 варианта A) |
| Сайт недоступен ночью | компьютер уходит в спящий режим — отключите сон |
| 502 от Cloudflare | приложение не отвечает: проверьте `npm start` и <http://127.0.0.1:8787/api/health> |
| Сайт на GitHub Pages не обновился | проверьте вкладку Actions: сборка могла упасть; локально запустите `python tools/sync-web-data.py` |
| Не могу войти в GitHub | восстановите доступ через резервные коды или приложение-аутентификатор; SMS в +375 приходит ненадёжно |
