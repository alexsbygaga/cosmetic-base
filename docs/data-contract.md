# Контракт данных каталога сырья

Каждая позиция каталога — один JSON-объект со следующими полями.

## Обязательные поля

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | Технический идентификатор из входного списка. **Не менять.** |
| `provenance` | string | Источник данных: `human` — позиция из исходного файла или добавлена человеком вручную; `ai` — найдена и заполнена ИИ. **Не менять**, значение приходит во входном списке (для новых позиций — `ai`). |
| `name_ru` | string | Название сырья по-русски (как в базе; допустимо исправить явные опечатки). |
| `name_lat` | string | Название латиницей / международное (INCI-имя, торговое имя или химическое название). |
| `inci` | string | Полное INCI-имя. Для смеси — все компоненты через `, `. **Всегда на английском, в официальной INCI-орфографии** (например `Cocamidopropyl Betaine`, а не `Cocamidopropilbetaine`). Исправить ошибки исходного файла. |
| `cas` | string | CAS-номер. Для смеси — номера компонентов через `; `. Для отдушки — `— (смесь, CAS не присвоен)`. |
| `category` | string | ID категории из входного списка. **Не менять**, если категория явно не ошибочна. |
| `aggregate_state` | string | Агрегатное состояние при 20–25 °C: `жидкость`, `вязкая жидкость`, `гель`, `паста`, `воск`, `твёрдое вещество (порошок)`, `твёрдое вещество (гранулы)`, `твёрдое вещество (хлопья)`, `масло`, `эмульсия`. |
| `origin` | string | Происхождение, одна из формулировок: `природное (растительное)`, `природное (животное)`, `природное (минеральное)`, `природное`, `синтетическое`, `полусинтетическое`, `природное/синтетическое (смесь)`, `биотехнологическое`. |
| `origin_details` | string | 1–3 предложения с обоснованием происхождения (источник, способ получения). |
| `description` | string | Детальное описание, 900–1800 знаков: что это, химическая природа, для чего применяется в косметике, ключевые свойства, ограничения. |
| `function_in_formula` | string | Технологическая функция: `эмульгатор (неионный)`, `анионный ПАВ`, `консервант`, `увлажнитель`, `загуститель` и т. д. |
| `tech_protocol` | string | Технологический протокол внесения, 700–1500 знаков: в какую фазу (A/B/C), при какой температуре, в каком порядке, нужна ли предварительная дисперсия/гидратация, скорость гомогенизации, особенности при охлаждении, совместимость и чего избегать. |
| `typical_usage` | string | Типовая дозировка (например `2–5 %`, `0,5–1 %`). |
| `ph_range` | string | Рабочий диапазон pH (например `3–9`). Если неприменимо — `—`. |
| `solubility` | string | Растворимость: `водорастворимо`, `маслорастворимо`, `диспергируется в воде`, `водорастворимо и маслорастворимо` и т. п. |
| `compatibility_notes` | string | 2–5 предложений: совместимость, конфликты, ограничения (катионные/анионные, электролиты, температурные пределы). |
| `regulatory` | string | Регуляторный статус: разрешено в ЕС/РФ, ограничения концентрации по Регламенту (EC) № 1223/2009, приложение (II/III/IV/V/VI), требования маркировки. Если данных нет — прямо указать, что не проверялось. |
| `synonyms` | string[] | Синонимы и торговые названия (может быть пустым массивом). |
| `components` | object[] | Для смесевого/торгового продукта: состав. Каждый элемент — `{"name": "...", "inci": "...", "cas": "...", "function": "..."}`. Для чистого вещества — пустой массив `[]`. |
| `references` | object[] | Ссылки: `{"title": "...", "url": "https://..."}`. 3–7 штук: Википедия, PubChem, CosIng, INCIDecoder, документация производителя. Только реально существующие URL. |
| `data_confidence` | string | `high` — данные подтверждены источниками; `medium` — часть данных оценена; `low` — позиция малоизвестна, данные предположительные. |
| `confidence_notes` | string | Что именно вызывает сомнение или требует проверки у поставщика. |

## Необязательные поля

| Поле | Тип | Описание |
|---|---|---|
| `extra` | object | Дополнительные сведения: `{"E_number": "E102", "CI_number": "CI 19140", "trade_name": "...", "producer": "...", "article": "..."}`. |
| `category_note` | string | Уточнение внутри категории (например «электролит-загуститель для ПАВ-систем» для поваренной соли). |

## Жёсткие правила

1. **Не выдумывать данные.** Если CAS-номер или свойство неизвестны — написать `—` или прямо указать предположение в `confidence_notes`. Никогда не подставлять правдоподобный, но непроверенный номер без пометки.
2. **`id`, `name_ru` и `category` берутся из входного списка буквально.** Остальное — результат анализа.
3. **Ссылки только реальные.** Использовать `https://pubchem.ncbi.nlm.nih.gov/`, `https://incidecoder.com/`, `https://ec.europa.eu/growth/tools-databases/cosing/`, `https://en.wikipedia.org/`, `https://ru.wikipedia.org/`, сайты производителей. Не придумывать URL.
3a. **Поле `provenance` брать из входного списка буквально** (`ai` или `human`) и не менять его.
4. **Для отдушек** (категория `fragrances`): `inci` = `Parfum`, `cas` = `— (смесь, CAS не присвоен)`. Если известен артикул и производитель (например `AVM-…` или `SD-…` — Syren; `V1502/1` — Новаком; `897992` — Доброфф), указать их в `extra` (`producer`, `article`) и описать ароматический профиль в `description`. `components` заполнять только для известных аллергенов/носителей, иначе пустой массив. Отдельно отметить, что полный состав раскрывается в документации поставщика (IFRA/аллергены).
5. **Для красителей**: указать `E_number` и `CI_number` в `extra`, `inci` = официальное INCI (например `CI 19140` для Тартразина — то есть для красителей INCI-имя совпадает с CI-номером). Указать регуляторные ограничения (например Тартразин запрещён в ЕС для продуктов, наносимых на кожу, но разрешён в средствах для волос; допускается только в средствах, смываемых с кожи).
6. **Для смесевых торговых продуктов** (`Эвагуард`, `Эуксил`, `Продью 500`, `Ceramide Complex CLR`, силиконовые эмульсии, `Vitamin B Complex`, `Экзосомы молока`): заполнить `components` максимально подробно, описать, что это смесь, и указать функции каждого компонента.
7. **Язык ответа — русский** для всех текстовых полей, кроме `inci` и `name_lat`.
