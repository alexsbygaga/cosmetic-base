# Косметическая база

Каталог косметического сырья: категории по типу сырья, INCI, CAS-номера, детальные
описания, технологические протоколы внесения, агрегатное состояние, происхождение
и ссылки на источники — плюс веб-интерфейс для поиска, фильтрации, сортировки
и редактирования базы.

Источник данных — файл `Косметическая база.xlsx` (129 позиций после объединения
дубликатов). Проект устроен как статический сайт: его можно открыть локально
и опубликовать на любом хостинге без сборки.

## Быстрый старт

```powershell
# из папки проекта
node server/serve.mjs
```

Откройте <http://127.0.0.1:8787>.

Дополнительные параметры:

```powershell
node server/serve.mjs --port 9000          # другой порт
node server/serve.mjs --host 0.0.0.0       # доступ из локальной сети
```

Сервер не требует зависимостей — только Node.js. Если Node нет под рукой, можно
запустить любой статический сервер из корня проекта, например
`python -m http.server 8787 --directory web`, но тогда будет недоступна запись
в `data/materials.json` (правки останутся в браузере).

## Доступ: гость, модератор, администратор

Каталог работает по трём ролям. Без входа доступен весь просмотр, а изменения —
только после входа.

| Возможность | Гость | Модератор | Администратор |
|---|:--:|:--:|:--:|
| Просмотр, поиск, фильтры, сортировка | да | да | да |
| **Категории, скрытые от гостей (отдушки)** | — | да | да |
| Экспорт каталога (JSON, CSV) | — | да | да |
| Загрузка каталога из файла JSON | — | да | да |
| Добавление позиций | — | да | да |
| Редактирование позиций и запись в файл | — | да | да |
| Удаление позиций | — | да | да |
| Список пользователей и назначение ролей | — | — | да |
| Журнал действий | — | — | да |

### Скрытые категории

По требованию заказчика **отдушки полностью скрыты от гостей**: сервер не отдаёт
эти позиции ни в каталоге, ни в выгрузке файлом — без права `catalog:restricted`
они не покидают сервер. Модератор и администратор видят их как обычно, а в
боковой панели у них есть переключатель «Скрытые от гостей».

Какие именно категории скрывать, задаётся в [data/categories.json](data/categories.json)
полем `hidden` — сейчас это `fragrances`. Изменить список:

```bash
python tools/set_category_visibility.py
```

В статической публикации (GitHub Pages и подобные) входа нет, поэтому скрытые
категории **не попадают в сборку**: их исключает [tools/sync-web-data.py](tools/sync-web-data.py),
а workflow проверяет это и останавливает публикацию, если они просочились.

Экспорт закрыт для гостя и на сервере: выгрузка файла (`GET /api/materials?download=1`)
без входа возвращает 401. Просмотр каталога при этом остаётся открытым — сайт
работает без авторизации.

Загрузка каталога из JSON выполняется в браузере, поэтому она ограничена правами
`catalog:import`: у гостя кнопки нет, а вызов действия приводит к предложению войти.
Так же устроены экспорт и правка — интерфейс скрывает недоступное, сервер проверяет
запись в файл.

Права проверяются **на сервере**: даже если запрос отправить в обход интерфейса,
гость получит 401, а модератор не сможет управлять пользователями (403).
Интерфейс лишь скрывает недоступные кнопки.

### Первый запуск

1. Запустите сервер: `node server/serve.mjs`.
2. Откройте сайт — появится форма «Первый запуск».
3. Задайте логин и пароль администратора (не короче 8 символов, минимум одна
   буква и одна цифра).

Пока администратора нет, форма настройки доступна всем, кто открыл сайт.
Поэтому **создайте администратора до публикации в интернете** или заранее
выполните:

```powershell
node server/create-admin.mjs admin "ВашПароль123" "Ваше имя"
```

Эта же команда помогает, если пароль администратора потерян: она меняет пароль
существующего пользователя и назначает ему роль `admin`. Сервис перечитывает файл
пользователей сам, поэтому созданный из консоли администратор может войти сразу —
перезапускать сервер не нужно.

### Управление пользователями

Администратор нажимает «Войти» в шапке → «Управление пользователями» и может:

* создать модератора или администратора;
* сменить роль, отключить или удалить пользователя;
* задать новый пароль (сессии этого пользователя завершаются).

Система не даёт остаться без администратора: нельзя снять роль, отключить или
удалить последнего администратора, а также удалить собственную учётную запись.

### Как это устроено

* Пароли хранятся как PBKDF2-HMAC-SHA256, 210 000 итераций, индивидуальная соль.
  В открытом виде пароль нигде не сохраняется.
* Вход выдаёт токен сессии (случайные 32 байта). Клиент хранит его в
  `localStorage` и отправляет в заголовке `Authorization`; сервер дополнительно
  ставит httpOnly-куку `cb_session`.
* Сессии живут 30 дней и переживают перезапуск сервера.
* Смена пароля завершает все сессии пользователя.
* Есть ограничение перебора паролей: 10 неудачных попыток на пару «адрес + логин»
  за 15 минут, дальше ответ 429. Успешный вход сбрасывает счётчик.
* Все значимые события пишутся в журнал `data/auth/audit.json` (вход, неудачный
  вход, создание и изменение пользователей, запись каталога).

Файлы аутентификации лежат в `data/auth/` и **не должны попадать в публичный
репозиторий** — они перечислены в `.gitignore`.

## Публикация в интернете

Проект не требует сборки: `web/` — статика, `server/serve.mjs` — API и статика.

**Вариант 1. Только статика** (GitHub Pages, Netlify, Cloudflare Pages, nginx):
публикуйте папку `web/`. Работает просмотр, поиск и фильтры; правки сохраняются
только в браузере посетителя. Аутентификация при этом недоступна — для неё нужен
серверный API, поэтому экспорт и правка не ограничиваются.

**Вариант 2. С сервером** (рекомендуется, если нужны правки и роли):

```bash
node server/serve.mjs --host 0.0.0.0 --port 8787
```

* поставьте сервер за обратный прокси (nginx, Caddy) и включите **HTTPS**:
  без него пароль и токен сессии передаются открытым текстом;
* если прокси передаёт реальный адрес клиента, добавьте `--trust-proxy`, чтобы
  ограничение перебора считалось по адресу посетителя, а не прокси;
* данные можно держать отдельно: `--data-dir /srv/cosmetic-data`;
* делайте резервные копии `data/materials.json` и `data/auth/` — первый содержит
  каталог, второй учётные записи.

Переменные окружения: `CB_HOST`, `CB_PORT`, `CB_DATA_DIR`, `CB_TRUST_PROXY=1`.

**Вариант 3. Бесплатный сервер Oracle Cloud** — рекомендованный, если нужны
и публичный сайт, и правки, которые сохраняются на сервере: у виртуальной машины
постоянный диск, поэтому каталог не сбрасывается при перезапуске.
Пошаговая инструкция: [docs/deploy-oracle.md](docs/deploy-oracle.md).

**Важно:** Oracle не регистрирует пользователей из Беларуси (и ряда других
стран). Если это ваш случай — смотрите
[docs/publish-without-cloud.md](docs/publish-without-cloud.md): там бесплатный
вариант «свой компьютер + Cloudflare Tunnel» (полный функционал, включая правки,
без зарубежной карты), недорогой VPS с оплатой через ЕРИП и публикация статики
на GitHub Pages или любом другом хостинге. Набор `deploy/` подходит любому
Linux-серверу, не только Oracle.

**Про GitHub:** там можно бесплатно опубликовать **каталог для просмотра**
(workflow [.github/workflows/pages.yml](.github/workflows/pages.yml) собирает
папку `web/`), но редактирование не заработает: раннеры GitHub Actions
временные, а приложению нужен постоянный диск для правок и файла пользователей.
Пошаговая инструкция для новичка: [docs/github-publish.md](docs/github-publish.md),
помощник в консоли: `node tools/github-setup.mjs check|init|publish|status`.

Всё для развёртывания лежит в `deploy/`:

| Файл | Назначение |
|---|---|
| `setup-oracle.sh` | Установка «под ключ»: Node.js, Caddy с HTTPS, systemd-сервис, таймеры бэкапа и keepalive, firewall |
| `cosmetic-base.service` | Автозапуск приложения, данные в `/var/lib/cosmetic-base` (вне кода) |
| `Caddyfile` | Обратный прокси с автоматическим сертификатом Let's Encrypt |
| `backup.sh` + `*.timer` | Ежедневный архив каталога и данных аутентификации |
| `keepalive.sh` + `*.timer` | Обновление DuckDNS и защита от отзыва простаивающего инстанса |
| `make-release.sh` | Сборка архива для загрузки на сервер |
| [tools/tunnel.mjs](tools/tunnel.mjs) | Публикация через Cloudflare Tunnel: `node tools/tunnel.mjs free \| setup \| run \| status` |

## Что умеет интерфейс

* **Поиск** по названию, латинскому названию, INCI, CAS, синонимам, составу
  смеси и описанию. Горячая клавиша `/` ставит фокус в строку поиска.
* **Фильтры** по категории, агрегатному состоянию и происхождению, а также
  режимы «только с полными данными» и «только изменённые мной».
* **Сортировка** по названию, категории, INCI и дате изменения; два вида —
  плитка и таблица (с сортировкой по клику на заголовок столбца).
* **Фильтры — в колонке слева**: категории с количеством позиций, агрегатное
  состояние, происхождение, переключатели «только с полными данными» и «только
  изменённые мной», кнопка сброса. Колонка закреплена и прокручивается отдельно.
  На планшете и телефоне она превращается в выдвижную панель по кнопке «Фильтры».
* **Каталог занимает остальную ширину**: 3 колонки блоков на широком мониторе,
  2 на ноутбуке и планшете, 1 на телефоне.
* **Карточка сырья открывается в центрированном попапе** и содержит все поля:
  описание, идентификация, физико-химические свойства, происхождение,
  технологический протокол, состав смеси, совместимость, регуляторный статус,
  синонимы и ссылки. На телефоне попап занимает весь экран.
* **Редактирование**, **удаление** и **создание** позиций прямо в браузере.
* **Экспорт** каталога в JSON и CSV, **импорт** из JSON, **запись** в файл
  `data/materials.json` через API сервера (с автоматическими резервными копиями
  в `data/backups`).
* **Светлая и тёмная темы**, полностью адаптивная вёрстка (телефон, планшет,
  настольный компьютер), печать каталога.

## Происхождение данных: человек или ИИ

У каждой позиции есть поле `provenance`:

| Значение | Что означает |
|---|---|
| `human` | Позиция из исходного файла «Косметическая база.xlsx» или добавлена человеком вручную через интерфейс. |
| `ai` | Компонент найден и заполнен ИИ по запросу — требует проверки технологом. |

В интерфейсе источник виден сразу: на карточке и в таблице стоит метка **«ИИ»** или
**«чел.»**, в попапе — «Добавлено ИИ» / «Добавлено человеком», а в боковой панели
есть фильтр **«Источник данных»** с количеством позиций. В строке статистики
показывается, сколько позиций добавил ИИ.

Список компонентов, которые нужно найти и заполнить, лежит в
`data/new-components.json` (его формирует `tools/new_components.py`). Результаты
сбора данных складываются в `data/enriched-ai/`, а `tools/build_catalog.py`
добавляет их в каталог с признаком `ai`.

## Где хранятся данные

| Файл | Назначение |
|---|---|
| `data/materials.json` | **Основной каталог.** Его читает и перезаписывает сервер. |
| `web/data/materials.json` | Копия каталога, встроенная в сайт. Используется, когда API недоступен. |
| `data/categories.json` | Справочник категорий сырья (id, название, цвет). |
| `data/raw-materials.source.json` | Исходный список из Excel с категориями и служебными полями. |
| `data/overrides.json` | **Ручные правки** поверх собранных данных. Применяются при каждой пересборке каталога. |
| `data/enriched/*.json` | Результаты сбора данных по исходной базе (промежуточные файлы). |
| `data/new-components.json` | План новых компонентов, которые добавляет ИИ (id, название, категория, INCI). |
| `data/enriched-ai/*.json` | Результаты сбора данных по новым компонентам ИИ. |
| `data/batches-ai/` | Входные партии для сбора данных по новым компонентам. |
| `data/backups/` | Автоматические резервные копии перед каждой записью (последние 20). |
| `docs/data-contract.md` | Контракт данных: все поля, правила и требования к качеству. |

### Ручные правки (`data/overrides.json`)

Если позицию нужно уточнить или исправить, править `data/enriched/*.json` не надо —
правка потеряется при следующей пересборке. Вместо этого добавьте запись в
`data/overrides.json`:

```json
{
  "overrides": [
    {
      "id": "peg-40",
      "reason": "почему внесена правка",
      "patch": {
        "inci": "PEG-40 Hydrogenated Castor Oil",
        "function_in_formula": "солюбилизатор; эмульгатор",
        "extra": { "hlb": "≈ 14–16" }
      }
    }
  ]
}
```

Поля внутри `patch` заменяют значение целиком, `extra` дополняется по ключам.
Скрипт `tools/build_catalog.py` применяет правки последним шагом и печатает их
список.

### Как сохраняются правки

Правки в интерфейсе мгновенно попадают в локальное хранилище браузера, поэтому
работать можно даже без сервера. Чтобы перенести их в файл каталога, нажмите
кнопку меню (три точки) → **«Сохранить в data/materials.json»**. Перед записью
сервер складывает текущий файл в `data/backups/`.

## Публикация на сервере

Проект не требует сборки: все файлы статические.

**Статический хостинг** (GitHub Pages, Netlify, Cloudflare Pages, nginx):

* корень публикации — папка `web/`;
* каталог читается из `web/data/materials.json`, правки сохраняются
  в браузере пользователя;
* экспорт и импорт JSON работают без сервера.

**С сервером** (полноценное редактирование с записью в файл):

* запустите `node server/serve.mjs --host 0.0.0.0` на сервере;
* раздавайте статику из `web/` и проксируйте `/api/*` на этот процесс;
* либо объедините: сервер сам раздаёт статику и API на одном порту.

## Поля каталога

Обязательные: `id`, `name_ru`, `name_lat`, `inci`, `cas`, `category`,
`aggregate_state`, `origin`, `origin_details`, `description`,
`function_in_formula`, `tech_protocol`, `typical_usage`, `ph_range`,
`solubility`, `compatibility_notes`, `regulatory`, `synonyms`, `components`,
`references`, `data_confidence`, `confidence_notes`.

Дополнительные: `category_note`, `extra` (производитель, артикул, номера E и CI,
торговое название, условия хранения), а также служебные `source_name`,
`source_inci`, `source_duplicate_rows`.

Полное описание каждого поля — в [`docs/data-contract.md`](docs/data-contract.md).

## Категории сырья

Категории задаются в `data/categories.json` и используются и в фильтрах, и в форме
редактирования. Чтобы добавить категорию, допишите объект с полями `id`, `ru`,
`en` и `color` — она сразу появится в интерфейсе.

## Пересборка каталога из данных

```powershell
python tools/build_catalog.py
```

Скрипт собирает `data/materials.json` из файлов `data/enriched/*.json`, сверяет
позиции с исходным списком, копирует результат в `web/data/materials.json`
и печатает отчёт: сколько позиций без CAS, без ссылок, с коротким описанием и т. д.

Другие скрипты в `tools/`:

| Скрипт | Назначение |
|---|---|
| `extract.py` | Извлекает и нормализует список сырья из Excel. |
| `recategorize.py` | Присваивает категории по названию сырья. |
| `plan.py`, `make_batches.py` | Формируют партии для сбора данных. |
| `build_catalog.py` | Собирает итоговый `materials.json` и печатает отчёт. |
| `validate_catalog.py` | Проверяет структуру каталога и ссылки. |
| `fixture.py` | Создаёт отладочный набор данных. |

Проверка прав по HTTP (нужен свободный порт):

```powershell
# 1. временная папка данных (сервер при этом должен быть остановлен)
python tools/prepare_auth_test.py
# 2. тестовый сервер
node server/serve.mjs --port 8791 --data-dir tools/auth-test-data
# 3. проверки в другом окне
$env:CB_BASE='http://127.0.0.1:8791'; $env:CB_DATA_DIR='tools/auth-test-data'
node server/tests/http-auth.test.mjs
```

Проверяются 29 сценариев: гость читает, но не пишет, не выгружает каталог и не
имеет права на импорт; настройка администратора; права модератора и администратора;
запрет повышения собственной роли; защита от перебора; завершение сессий; журнал
действий.

Тесты логики каталога работают без браузера: они подменяют `localStorage` и `fetch`
и прогоняют модуль состояния на реальном `data/materials.json`.

## Требования

* Node.js 18+ — для локального сервера (зависимостей нет).
* Python 3.9+ с `openpyxl` — только для скриптов пересборки данных.
* Браузер: Chrome, Edge, Firefox, Safari последних версий.

## Ограничения данных

Часть сведений о сырье (особенно о торговых марках, отдушках и смесевых
продуктах) не публикуется производителями открыто. Для таких позиций поле
`data_confidence` имеет значение `medium` или `low`, а в `confidence_notes`
перечислено, что именно нужно уточнить у поставщика — чаще всего артикул,
полный состав, аллергенный профиль и IFRA-сертификат. Эти поля стоит
отредактировать после получения спецификаций.
